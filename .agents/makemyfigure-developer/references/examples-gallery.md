# Examples, galleries and the plot catalogue

Documented from the code on branch `feature/makemyfigure-developer-agent` (forked from
`main` on 2026-09-17, version `1.1.0`). Paths are relative to the repository root.
Plot counts are deliberately not stated as facts here; enumerate them from
`make_my_figure_core.plots.registry.available_plot_types()` when you need them.

## 1. The three data sources and what each is for

| Location | Produced by | Purpose | Tracked in git |
|---|---|---|---|
| `examples/by_plot_type/<slug>/` (+ `examples/example_data_manifest.json`, `examples/Make_My_Figure_All_Example_Data.xlsx`) | `scripts/generate_example_data.py` | the **bundled example** every plot type must have; loaded by "Use example data" in both apps, by the manuals' plot catalogue, and by most QA galleries | yes (all formats, README, plotspec) |
| `examples/statistics/<slug>/` (+ `manifest.json`) | `scripts/generate_stats_examples.py` | one synthetic dataset per statistical workflow with an embedded `StatsSpec` and an `expected_method_report.md` | yes (PNG/PDF/SVG renders are git-ignored) |
| `examples/matrix_workflow/`, `examples/preprocessing_workflow/`, `examples/multi_sheet_workbook/` | `make_my_figure_core/matrix_workflow/examples.py::write_examples`, `scripts/generate_multi_sheet_fixture.py` | fixtures for the Matrix Workflow (`expected_recommendations.json` is a golden file), preprocessing, and the multi-sheet Excel loader | yes |
| `mock_data/*.csv|tsv` (+ `plot_schema_manifest.json`) | hand-authored early in the project (manifest says v0.1.0) | the **renderer unit-test fixtures**; `tests/conftest.py::plot_case` maps a subset of plot types to these files (`MOCK_DIR`); `scripts/build_figure_preset_qc.py` uses a mock file as the "different dataset of the same type" when one exists | yes |
| `make_my_figure_mock_data.xlsx` (root) | legacy workbook | historical; root `*.xlsx` is otherwise git-ignored, this one is tracked | yes |

`make_my_figure_core/examples.py` is the loader: `has_manifest()`, `load_manifest()` (lru-cached), `entry(plot_type)`, `plot_types_with_examples()`, `has_example(plot_type)`, `template_path(plot_type, ext)`, `example_readme(plot_type)`, `load_example(plot_type) -> (TableInfo, aux_tables, plotspec)`. Paths resolve through `make_my_figure_core/resources.py` (`project_base()`, `resource_path()`, `MAKE_MY_FIGURE_RESOURCES` override) so the same code works in a checkout, an installed wheel, or a PyInstaller bundle. Note: `examples.example_slug` does **not** exist; `scripts/build_plot_catalog_part.py` guards for it with `hasattr` and falls back to the folder name of `template_path`.

App entry points: `apps/desktop_app/controller.py::DesktopController.load_example(plot_type)` and the Streamlit sample chooser (`examples.plot_types_with_examples()` / `examples.load_example` in `apps/streamlit_app/streamlit_app.py`).

Packaging: `MANIFEST.in` grafts `schemas`, `style_profiles`, `mock_data`, `examples`; `setup.py` stages them into the package at build time; `tests/test_package_data.py` checks that the bundled dir lists, the MANIFEST grafts and `pyproject.toml` `[tool.setuptools.package-data]` agree, and that a built wheel can render every plot type.

## 2. How a bundled example is generated deterministically

`scripts/generate_example_data.py`:

- Module constants: `SEED = 42`, `LICENSE = "CC0-1.0"`, `SOURCE = "generated by scripts/generate_example_data.py"`, `STYLES = ["publication"]`, `EXAMPLES_DIR`, `BY_PLOT_DIR`, `COMBINED_XLSX`, `MANIFEST_PATH`.
- One builder function per plot type, named `b_<slug>(rng) -> (primary_df, aux_df_or_None)`; `rng` is a `numpy.random.Generator`.
- One `Example(plot_type, slug, sheet, use_case, builder, required_columns, optional_columns, replace_help, common_mistakes, aux_name=None)` entry per plot type in the module-level `EXAMPLES` list.
- **Seed convention:** in `main()` each example is seeded `np.random.default_rng(SEED + i)` where `i` is its index in `EXAMPLES`. Therefore **append new examples at the end of the list** — inserting in the middle reseeds and silently rewrites every example after it (the inline comment above the histogram entry says exactly this). The network example additionally writes alternate input files with `default_rng(SEED + 777)` (`write_network_extra_files`).
- Per example it writes `data.csv`, `data.tsv`, `data.xlsx` (`_write_table`), optional `<aux_name>.csv/.tsv/.xlsx`, `plotspec.json` (from `registry.default_mapping`, `journal_style: "publication"`, 89 × 70 mm, 300 dpi, formats svg/png/pdf), and `README.md` (`_readme`), then a manifest entry with `required_columns`, `optional_columns`, `files`, `aux_tables`, `excel_sheet`, `recommended_style_profiles`, `compatible_renderers`, `expected_export_formats`, `data_type: "synthetic"`, `license`, `provenance`, `n_rows`, `user_replacement_note`, `common_mistakes`.
- Finally the combined workbook (one sheet per example; sheet names truncated to 31 chars and de-duplicated) and `examples/example_data_manifest.json`.

Other deterministic generators follow the same pattern: `generate_stats_examples.py` (fixed seed, writes only under `examples/statistics/`), `matrix_workflow/examples.py` (`build_example_matrix(seed=7)`, `build_precomputed_differential(seed=11)`, 300 features, 6 Ctrl + 6 Treatment samples, biotype annotation columns).

All example data are synthetic and CC0; `docs/EXAMPLE_DATA.md` and `docs/DATA_TEMPLATES.md` are the user-facing statements of this policy, and `tests/test_examples.py::test_manifest_is_all_synthetic_cc0` enforces it.

## 3. Tests that pin the example system

`tests/test_examples.py` (parametrised over manifest entries): `test_manifest_present`, `test_every_supported_plot_type_has_example` (registry minus manifest must be empty), `test_manifest_is_all_synthetic_cc0`, `test_manifest_entry_complete` (`REQUIRED_MANIFEST_KEYS`), `test_all_formats_exist_and_load`, `test_required_columns_present`, `test_plotspec_validates`, `test_example_renders`, `test_example_exports_all_formats`, `test_combined_workbook_has_all_sheets` (`EXPECTED_SHEETS` is a fixed subset of sheet names — add the new sheet there if you want it pinned), `test_readme_per_plot_exists`.

`tests/test_stats_examples.py` renders every statistics example with its method sentence. `tests/test_renderers.py` and `tests/test_v04_plots.py` render from `mock_data` and assert the input frame is unchanged (`pd.testing.assert_frame_equal`). Two tests hard-code the registry size: `tests/test_renderers_m2.py` and `tests/test_desktop_controller.py` (`assert len(...) == N`).

## 3a. Statistics examples (`examples/statistics/`)

`scripts/generate_stats_examples.py` writes one folder per statistical workflow slug
(`two_group_unpaired`, `two_group_paired`, `nonparametric`, `one_way_anova`,
`two_way_anova`, `repeated_measures`, `grouped_within_dose`, `scatter_correlation`,
`survival_km`, `categorical_2x2`, `contingency_large` on this commit). Each folder holds
`data.csv/tsv/xlsx`, `plotspec.json` (PlotSpec with an embedded `StatsSpec`),
`statsspec.json` (the StatsSpec alone), `README.md` (design + required columns) and
`expected_method_report.md` (the method sentence the engine produced). The manifest
`examples/statistics/manifest.json` lists `slug`, `plot_type`, `test`,
`comparison_mode`, `n_rows`, `columns` per example. Rendered PNG/PDF/SVG in these folders
are git-ignored. `tests/test_stats_examples.py` renders each with its method sentence
and checks the file set; `scripts/generate_stats_qa_gallery.py` tiles them for eyeballing.

If a new plot type supports on-figure statistics, add a workflow here so the method
sentence and bracket layout are exercised on a bundled dataset.

## 3b. The in-app template flow

Both apps expose the bundled example as a starting template. Desktop:
`DesktopController.load_example` loads it, and the "Save template (example table)"
button (`apps/desktop_app/main.py`) copies the file returned by
`examples.template_path(plot_type, ext)` (falls back to the CSV). `docs/DATA_TEMPLATES.md`
describes the user-side rules (keep required column names, replace rows). This is why
every example's `required_columns` in the manifest must match what the renderer's
default mapping expects — `tests/test_examples.py::test_required_columns_present` and
`test_plotspec_validates` enforce it.

## 3c. Publication-recreation benchmarks (published-panel benchmark)

Three benchmark suites live under `benchmarks/`; all render through
`registry.render` with the Publication style and store no copyrighted figure unless the
licence clearly permits it.

- `benchmarks/publication_recreation/` — the v0.6 suite. `manifest.json` has top-level
  `schema`, `policy`, `style`, `n_entries`, `n_passed`, `benchmarks`; each benchmark entry
  records `benchmark_id`, `paper_title`, `authors`, `year`, `doi_or_url`, `data_source`,
  `data_license`, `license_url`, `license_verified`, `figure_license`, `figure_panel`,
  `target_description`, `plot_type`, `app_renderer`, `transforms`, `plotspec_path`,
  `qc_path`, `output_path`, `iterations`, `scientific_qc_pass`, `visual_qc_pass`,
  `exports_pass`, `passed`, `reference_image_stored`, `known_differences`, `style`.
  Committed per panel: `recreated_panels/<id>/plotspec.json`, optional `statspec.json`,
  and `qc/{scientific_qc.md,visual_qc.md,recreation_delta_report.md}`; rendered
  `figures/` and `datasets/*/raw/` are git-ignored. Scripts:
  `scripts/{discover_candidates,curate_benchmark_data,download_benchmark_assets,
  recreate_panels,evaluate_recreations,generate_contact_sheets,validate_manifest,
  pipeline}.py` with shared `benchmark_lib.py`. Reports:
  `reports/V0_6_PUBLICATION_RECREATION_REPORT.md`, `benchmark_summary_table.csv`,
  `failed_or_rejected_candidates.md`. Tests: `tests/test_publication_recreation_manifest.py`
  (permissive licences only, no reference images, QC flags required, no journal names),
  `tests/test_publication_recreation_pipeline.py` (offline recreation, graceful download skip),
  `tests/test_publication_recreation_exports.py`.
- `benchmarks/one_publication_recreation/` — the Gorman et al. 2014 penguins pilot:
  `publication_manifest.json`, `raw_data/`, `processed_data/`, `recreated_panels/panel_A..C`,
  `figure_builder/` (FigureSpec + composite), `qc/`. `tests/test_one_publication_recreation.py`
  checks honesty labels (no significance brackets where the paper's model is not reproduced).
- `benchmarks/ten_publication_recreation/` — ten CC-BY papers, each with a viewed
  published figure, recreated from public data; `manifest.json`, `_records.json`,
  `publications/<id>/`, `side_by_side/`, `reports/`. `tests/test_ten_publication_recreation.py`
  checks per-publication artefacts, licence of any stored reference figure, and that no
  text claims an exact reproduction.

A new plot type gets a benchmark panel only when a permissively licensed public dataset
exists for it; otherwise the synthetic example is the only coverage, and the
`docs/PUBLICATION_BENCHMARKS.md` policy (`data_kind`, `status: target_only`) applies.

## 4. Galleries and QA renders — what exists, where it writes, what is tracked

All of these render **through** `make_my_figure_core.plots.registry.render` / `render_to_files` with the Publication style; none draws with raw matplotlib except `build_manual_diagrams.py` (schematics, not plots).

## 5. The manuals' plot catalogue and diagrams

- `scripts/build_plot_catalog_part.py` writes `docs/manuals/User_Manual/parts/03_plot_catalog.md` ("Part X — Plot catalogue"). `section(pt)` assembles each entry **from code**: `registry.display_name`, `ui_hints.column_fields` / `ui_hints.options` (split by `Option.scope` into style vs config), `styles.capabilities.get_style_capabilities`, `audit_style_capabilities.scan_renderer`, and the example's columns + mapping from `examples.load_example`. Only the `PURPOSE`, `STATS_PLOTS` and `LIMITS` dicts at the top of the script are hand-written prose — a new plot type without entries there gets empty Purpose/When-to-use lines and a generic limitations sentence.
- Each entry ends with an image link `../../assets/figures/<plot_type>.png`. **No committed script renders those PNGs.** `docs/manuals/assets/figures/` was added in commit `031cf2f` ("Add the User Manual and Quick Start sources, assets and build tooling") and nothing under `scripts/` writes to it. For a new plot type you must render the example yourself (e.g. `render_to_files(make_spec(pt, "data.csv", "publication"), df, base_path=..., formats=["png"])`) and save it under that name, or the PDF build will have a broken figure reference.
- `scripts/build_manual_diagrams.py` draws the workflow schematics into `docs/manuals/assets/diagrams/` (PNG + SVG). It contains a hard-coded plot count inside a box label ("Choose a plot (N types)") — update it when the registry grows.
- `scripts/build_manuals.py` assembles the parts and stamps version/commit/date; see `documentation.md`.

The catalogue's committed header sentence also states the count of plot types (written by `main()` from `len(available_plot_types())`), so it is only correct if the script was re-run after the registry changed.

## 6. What is regenerated at release time

From `docs/RELEASE_CHECKLIST.md`, `docs/releases/v1.1.0/release_v1.1.0_audit.md`, `docs/manuals/audit/known_documentation_limitations.md` ("Rebuilding") and `.github/workflows/build_desktop_releases.yml`:

- CI (`build_desktop_releases.yml`) only runs `scripts/make_icons.py`, the platform build scripts and PyInstaller with a `--selftest`. **It does not regenerate examples, galleries or manuals.**
- The v1.1.0 audit records that the manuals PDFs attached to the release were byte copies of the committed PDFs, that `reports/figure_preset_qc/` was regenerated for the release, and that `reports/release_cross_platform_qc/` was refreshed per platform.
- Everything else (examples, catalogue part, catalogue figures, screenshots, QC summaries under `reports/`) is regenerated **manually** by the developer and committed. There is no Makefile or single "rebuild all" script on main.

## 7. Checklist: give a new plot type an example and gallery presence

Assumes the renderer is registered (`plots/<name>.py`, `registry._RENDERERS`, `_DEFAULT_MAPPINGS`, `_DISPLAY_NAMES`, `ui_hints.COLUMN_FIELDS`, `ui_hints.OPTIONS`).

1. `scripts/generate_example_data.py`: add `b_<slug>(rng)` returning a small, plausible synthetic table (and an aux table if the renderer needs one, with `aux_name`); **append** an `Example(...)` to the end of `EXAMPLES` with a unique Excel sheet name (≤ 31 chars), required/optional columns, `replace_help`, `common_mistakes`. Run `python scripts/generate_example_data.py`; confirm only the new folder plus the manifest/workbook changed (`git status examples/`).
2. Optionally add `mock_data/<file>` and an entry in `tests/conftest.py::plot_case` mapping and `mock_data/plot_schema_manifest.json` if the type should be in the renderer unit tests and preset-QC "second dataset"; otherwise `build_figure_preset_qc._new_dataset` perturbs the example.
3. Run `MPLBACKEND=Agg python -m pytest -q -p no:pytest-qt tests/test_examples.py tests/test_publication_style.py tests/test_desktop_controller.py tests/test_renderers_m2.py`; update the two hard-coded registry-size assertions.
4. Statistics: if the plot supports on-figure stats, add a workflow to `scripts/generate_stats_examples.py` and re-run it.
5. Recommendations: only if there is a detectable data signature — see `recommendations.md` §5.
6. Regenerate tracked QA artefacts that enumerate the registry: `python scripts/build_figure_preset_qc.py` (fails on any FAIL), `python scripts/audit_style_capabilities.py`, `python scripts/generate_publication_qc_gallery.py`, `python scripts/generate_figure_qc_gallery.py`, `python scripts/run_cross_platform_qc.py --output reports/release_cross_platform_qc/current_platform`. Inspect the PNGs even though they are not committed.
7. Catalogue: add `PURPOSE[pt]`, `LIMITS[pt]` (and `STATS_PLOTS[pt]` if applicable) in `scripts/build_plot_catalog_part.py`; render `docs/manuals/assets/figures/<plot_type>.png` from the example with Publication defaults; run `python scripts/build_plot_catalog_part.py`; update the count in `scripts/build_manual_diagrams.py` and re-run it; then `python scripts/build_manuals.py`.
8. Docs: README §3 list and the plot-types badge, `docs/PLOT_TYPE_REQUIREMENTS.md` (or the release-specific plot-types doc), CHANGELOG `Unreleased`. See `documentation.md` for the per-plot template.
9. Commit the regenerated `examples/`, `reports/figure_preset_qc/`, `reports/publication_qc_gallery/*.csv|md`, `reports/figure_qc_release_candidate/*`, `docs/manuals/User_Manual/parts/03_plot_catalog.md`, `docs/manuals/assets/figures/<pt>.png`, `docs/manuals/assets/diagrams/*`, and the rebuilt manual MD/DOCX/PDF together with the code so the tree stays self-consistent.
