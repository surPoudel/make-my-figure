# MakeMyFigure architecture (main, documented 2026-09-17)

Authoritative tree: the `main` branch of this repository. A separate worktree at
`../make_my_plot_journal_presets` (branch `feature/evidence-derived-journal-presets`)
carries unmerged work (Figure Package, experimental presets, rewritten box/violin and
bar renderers, an observations engine). Nothing from that branch is described here
unless explicitly flagged; none of it exists on `main`.

## 1. Top-level layout

| Path | Role |
|---|---|
| `make_my_figure_core/` | The frontend-agnostic engine. The only importable package (`pyproject.toml` `packages.find.include = ["make_my_figure_core*"]`). |
| `apps/desktop_app/` | PySide6 desktop app. Not packaged as a wheel; run from a checkout or frozen with PyInstaller (`packaging/`). |
| `apps/streamlit_app/` | Browser app (`streamlit_app.py` + `matrix_wizard.py`). |
| `schemas/plot_spec.schema.json` | The PlotSpec JSON schema (Draft 2020-12). |
| `style_profiles/` | `starter_journal_style_profiles.json` + `learned/*.json`. Only `publication` is user-visible (v0.6+). |
| `examples/` | Generated per-plot example datasets + manifest (see data-mapping.md). |
| `mock_data/` | Older hand-maintained sample tables + `plot_schema_manifest.json`; fallback when `examples/` is missing. |
| `scripts/` | Generators, audits, QC galleries, manuscript builders. |
| `tests/` | pytest suite (`conftest.py` forces `matplotlib.use("Agg")`). |
| `docs/` | User/developer docs (`PLOT_TYPE_REQUIREMENTS.md`, `STATISTICS.md`, `MATRIX_WORKFLOW.md`, ...). |

Resource folders (`schemas`, `style_profiles`, `mock_data`, `examples`) are reached only
through `make_my_figure_core/resources.py::resource_path()`. `project_base()` resolves, in
order: PyInstaller `sys._MEIPASS`, the `MAKE_MY_FIGURE_RESOURCES` env override, the staged
`make_my_figure_core/_bundled/` copy (installed wheel), then the checkout root.
`BUNDLED_DIRS` is duplicated in `setup.py`; `tests/test_package_data.py` keeps them in step.

## 2. Core subpackages and modules

`make_my_figure_core/__init__.py` re-exports the public surface: `__version__`,
`load_table`, `TableInfo`, `validate_plot_spec`, `SpecValidationError`, `StyleProfile`,
`load_profile`, `list_profiles`, `render`, `render_to_files`, `available_plot_types`,
`display_name`, `default_mapping`, `make_spec`, `export_bundle_bytes`, `figure_to_bytes`,
`RenderResult`, `mock_data` (= `data` module), `presets`, `resource_path`.

### plots/
- `registry.py` - the dispatch tables and render/export entry points (see registry.md).
- `base.py` - `RenderResult`, `RenderError`, and every shared helper renderers use
  (see renderer-contract.md).
- One module per plot type (`barplot.py`, `volcano.py`, ...), each defining `PLOT_TYPE`
  and `render(spec, df, style)`.
- `_v04_shared.py` - matrix parsing, linkage, jitter/beeswarm layout, `ordered_unique`,
  `pick_column`, `neg_log10`.
- `stats_integration.py` (`run_and_annotate`) and `stats_overlay.py` (bracket / corner
  panel drawing) - the only path by which statistics reach a figure.
- `label_policy.py` - duplicate-label handling shared by volcano and MA plots.
- `annotation_state.py` - click-to-label state that round-trips into the PlotSpec.
- `handoff.py` - `PlotEditorHandoff`, the object the Matrix Workflow hands to the
  ordinary plot editor (both frontends consume it).

### styles/
- `engine.py` - `StyleProfile` dataclass (typography, axes, marks, legend, sizing,
  palette, colormaps), `rc_params()`, `apply()` (an `mpl.rc_context`), `with_overrides()`
  (applies `spec["style"]`), palettes (`NAMED_PALETTES`, `USER_PALETTES`),
  `WIDTH_PRESETS_MM`, `list_profiles()`, `load_profile()`, legacy journal-name migration
  (`LEGACY_STYLE_ALIASES`, `normalize_style_name`).
- `capabilities.py` - per-plot `PlotStyleCapabilities`; `_CAPS` is GENERATED by
  `scripts/audit_style_capabilities.py --write`. Used by the render path to warn about
  ignored style controls and by the GUIs to grey out controls.
- `publication_style_engine.py` - `publication_profile()`, `recommended_overrides()`.

### spec/
- `validate.py` - `load_schema`, `validate_plot_spec(spec, known_plot_types=, known_styles=)`,
  `default_output_block()`, `SpecValidationError(errors: list[str])`.

### statistics/
Frontend-agnostic tests and reporting: `runner.run_statistics` (dispatch),
`test_registry.TESTS` / `recommend_tests` (advisory), `schemas` (StatsSpec defaults,
`normalize_stats_spec`, `stats_sidecar_payload`), `models` (`StatResult`, `StatsReport`,
`StatsError`), `annotations` (`AnnotationItem`, `build_pairwise_annotations`,
`stat_text_panel`), plus `anova`, `nonparametric`, `pairwise`, `categorical`, `survival`,
`regression` (`glm_regression`), `effect_sizes`, `multiple_testing`, `method_reporting`.

### panels/
Multi-panel Figure Builder: `models` (`Panel`, `FigureLayout`, `MultiPanelFigure`),
`builder` (`build_figure`, `export_multipanel`, `multipanel_sidecar`, `draft_legend`,
`import_external_panel`). Panels re-render each PlotSpec through `registry.render`.

### recommendations/
`data_profiler.profile_table` -> `DataProfile` with `ColumnRole`s; `schema_detector`;
`plot_recommender.recommend_plots` (only registered renderers, drafts PlotSpecs via
`make_spec`); `recommendation_runner.recommend_for_table` / `recommend_after_analysis`;
`stat_recommender.suggest_stats`.

### qc/ and qa/
- `qa/publication_check.check_publication_readiness(fig)` and
  `qa/layout_qc.check_layout` / `auto_fix_layout` run inside `registry.render` on every
  figure (advisory; results land in `metadata["publication_check"]` / `["layout_qc"]`).
- `qc/publication_score.score_publication` + `qc/auto_fix.suggest_fixes/apply_fixes` are
  called on demand by the frontends (desktop `controller.publication_qc`).

### io/
`loaders.py` (`load_table`, `TableInfo`, `LoaderError`, `table_info_from_dataframe`) and
`workbook.py` (multi-sheet Excel inspection, classification, preview, `load_excel_sheet`
with worksheet provenance, output-name helpers). Details in data-mapping.md.

### examples.py and data.py
`examples.py` reads `examples/example_data_manifest.json` (`load_example`, `entry`,
`plot_types_with_examples`, `template_path`). `data.py` is the older `mock_data/` bundle
(`SAMPLE_FILES`, `load_sample`, PCA metadata special case). Frontends prefer `examples`
and fall back to `data`.

### ui_hints.py and ui_strings.py
`ui_hints` declares, per plot type, which mapping keys are column choosers
(`COLUMN_FIELDS`), which extra options exist (`OPTIONS: dict[str, list[Option]]`), which
roles take several columns (`MULTI_COLUMN_FIELDS`), and PCA metadata roles. Both
frontends build their controls from it. `ui_strings` holds shared labels
(`PLOT_TYPE_PLACEHOLDER`, `STYLE_DISPLAY_NAME`, ...).

### matrix_workflow/
Feature-by-sample matrix workflow: `MatrixSpec`/`SampleMetadataSpec`, validators,
normalization/transformations/preprocessing, QC diagnostics and QC plots,
`recommendations.recommend_plots`, `differential_summary`, `plot_builder.build_plot_inputs`
(turns a recommendation into a DataFrame + mapping + aux for `registry.render`),
`examples.write_examples` (writes `examples/matrix_workflow/`). Optional `count_model_de`
(PyDESeq2 extra).

### harvest/
License-aware open-access figure harvesting (Europe PMC / NCBI). Standalone tooling
(`scripts/harvest_library.py`); not on the render path.

### Other top-level modules
`annotations.py` (universal manual annotation layer, `parse_annotations`/`apply_annotations`),
`clustering.py` (SciPy linkage, scaling, `ClusteringError`), `transforms.py`
(`wide_to_long`, `correlation_matrix`, `value_counts`, `apply_transform`), `grouping.py`
(matrix melt/group helpers, `value_matrix_columns`), `differential.py` and `de_detect.py`
(simple feature screen and DE-column alias detection), `figure_import.py` (raster/PDF/SVG
panel import), `presets.py` (`.mmfpreset.json` figure presets and `.mmflayout.json`
layout presets; splits mapping into roles vs options using `ui_hints`), `version.py`.

## 3. Data flow: table -> PlotSpec -> figure -> export

1. **Load**: `io.loaders.load_table(path|bytes|file)` -> `TableInfo` (DataFrame +
   numeric/categorical column lists + missing-value counts + warnings + optional
   worksheet provenance). Excel workbooks go through `io.workbook.inspect_excel_workbook`
   -> `load_excel_sheet`.
2. **Map**: the frontend asks `ui_hints.column_fields(plot_type)` /
   `ui_hints.options(plot_type)` and `registry.default_mapping(plot_type)` and builds the
   `mapping` dict (column roles and plot options share one dict).
3. **Spec**: `registry.make_spec(...)` (Streamlit, recommender) or
   `DesktopController.build_spec(...)` (desktop) assembles
   `{plot_type, input_table, mapping, journal_style, output, layout?, statistics?, source?}`.
4. **Render**: `registry.render(spec, df, style=None, validate=True, aux=None)`:
   legacy style migration -> `validate_plot_spec` -> `load_profile` +
   `with_overrides(spec["style"])` -> capability warnings -> renderer dispatch (`aux`
   passed only when the renderer signature declares it) -> `apply_publication_layout`
   -> uniform legend placement -> stamp `spec` into metadata -> manual annotations ->
   publication check -> layout QC. Returns `RenderResult`.
5. **Export**: `export_figure(fig, base_path, formats, dpi)` (svg/png/pdf/tiff/eps, tight
   bbox, editable vector text via `_VECTOR_TEXT_RC`), `write_sidecar` (`*.plot_spec.json`),
   `write_stats_sidecar` (`*.stats_spec.json`), or in-memory `figure_to_bytes` /
   `export_bundle_bytes` (ZIP). `render_to_files` chains render + export + sidecars.

## 4. Which frontend consumes which core API

**Desktop** (`apps/desktop_app/`): `controller.py::DesktopController` is the only layer
that talks to the core; `main.py` (Qt widgets) calls the controller. Controller uses
`registry` (`available_plot_types`, `default_mapping`, `display_name`, `render`,
`export_figure`, `export_bundle_bytes`, `write_sidecar`), `ui_hints`, `examples`, `data`,
`io.loaders`, `io.workbook`, `spec.validate`, `styles.engine`, `statistics`
(`TESTS`, `recommend_tests`, `run_statistics`, `normalize_stats_spec`), `recommendations`,
`qc`, `matrix_workflow`, `grouping`, `transforms`, `differential`, `version`.
`main.py` also imports `ui_hints`, `registry.display_name`, `styles.engine.USER_PALETTES`,
`ui_strings`. Sub-panels: `stats_panel.py`, `panels_dock.py` (Figure Builder),
`recommendations_panel.py`, `grouping_panel.py`, `matrix_wizard.py`, `workers.py`
(QThreadPool tasks), `help_content.py`.

**Streamlit** (`apps/streamlit_app/streamlit_app.py`): a single top-to-bottom script that
imports `ui_hints`, `io.loaders`, `io.workbook`, `registry` (`available_plot_types`,
`default_mapping`, `display_name`, `make_spec`, `render`, `figure_to_bytes`),
`spec.validate`, `styles.engine`, `styles.capabilities`, `examples`, `grouping`,
`recommendations`, `statistics`, `presets`, `ui_strings`, `plots.annotation_state`,
`plots.label_policy`. It keeps its own copy of the legacy `SAMPLE_FILES` map for the
`mock_data` fallback (lines ~48-70).

Both frontends render through the same `registry.render` and, for the Matrix Workflow,
open the same `PlotEditorHandoff`.

## 5. Generated versus hand-written

Generated (do not hand-edit; rerun the generator):
- `examples/**` and `examples/example_data_manifest.json` - `scripts/generate_example_data.py`.
- `examples/statistics/**` + `manifest.json` - `scripts/generate_stats_examples.py`.
- `examples/matrix_workflow/**` - `make_my_figure_core/matrix_workflow/examples.write_examples`.
- `make_my_figure_core/styles/capabilities.py::_CAPS` - `scripts/audit_style_capabilities.py --write`
  (the flags are scanned from renderer source; reasons live in the script's `_REASONS`).
- `reports/**` QC galleries - `scripts/generate_*_gallery.py`, `scripts/build_figure_preset_qc.py`.

Hand-written: everything else in `make_my_figure_core/`, `apps/`, `schemas/`,
`mock_data/` (and its `plot_schema_manifest.json`, last stamped version 0.1.0),
`style_profiles/starter_journal_style_profiles.json`.

## 6. Single source of version truth

`make_my_figure_core/version.py::__version__` (currently the string read by
`pyproject.toml` `[tool.setuptools.dynamic] version = { attr = ... }`). The desktop About
dialog and `build_banner()` / `build_info()` read the same symbol. Do not add a version
string anywhere else; `CHANGELOG.md` records releases but is not read by code.
