## Summary

* **FALSE today:** #22 (the sentence the author noticed).
* **TOO STRONG today:** #16, #25–27, #31, #74, #76, #80–81, #85, #88, #121 — every use of "writes/written" for MatrixSpec, SampleMetadataSpec, PreprocessingSpec, and "every export" for PlotSpec/StatsSpec.
* **NEEDS REWORDING:** #3, #13, #28, #127 ("records the source data" → "records the identity/checksum of the source data"), and, after v1.1.1, #24/#42/#68 (add the figure package as the way to remove the data dependency).
* **Becomes true after v1.1.1:** the strong forms of #16, #22, #25–27, #74, #85 when phrased around the figure package; #71/#73/#136 flip from "not reopened" to "reopened from a figure package in both interfaces".
* **Unchanged / true today:** the Spec definitions, the Fig. 3 round trips as actually run, the R validation, the published-panel recreation, Table 1.

## Target story (only after author acceptance of v1.1.1)

PlotSpec: machine-readable record of one plot (recipe; source data required). Figure Preset: reusable configuration
without data. Figure Package: portable artifact containing the frozen data and every specification required to reopen
the figure, verified by checksum, opened from either interface. This is scientifically stronger than claiming that a
PlotSpec alone contains everything, and it is what the code will do.
