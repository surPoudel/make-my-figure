# v1.1.1 candidate — manual acceptance test for the author

Branch `feature/portable-figure-package-v1.1.1` (worktree `make_my_plot_v111`). **Nothing is tagged, released or merged.**
Run the desktop app from the worktree with the interpreter that has PySide6:

```
cd "…\make_my_plot_v111"
python -m apps.desktop_app.main
```

(or build a local one-folder bundle with `python scripts/build_desktop.py` and start `dist/MakeMyFigure/MakeMyFigure.exe`;
`MakeMyFigure.exe --selftest` must print `OK` — the self-test now saves, reopens and re-renders a figure package for
every plot type.) The status bar must show `v1.1.0 (<commit>)` with the feature-branch commit.

Tick every box only when the observed behaviour matches. Note anything that surprised you.

## TEST 1 — simple plot

1. Landing page → **Open data file** → `examples/by_plot_type/scatter_regression/data.csv` (or your own table).
2. Choose *Scatter plot with regression*, map x/y, change the palette, marker size, title and axis labels.
3. **5. Export → Save Figure Package (.mmfpackage)**. Read the dialog: it must say that the package includes the data,
   list the table with its shape and "+ original file", the records (PlotSpec, previews) and an estimated size. Save as
   `test1.mmfpackage`.
4. Close the application.
5. Move `test1.mmfpackage` to another folder (a USB stick or a different drive is ideal). Rename or move the original
   `data.csv` so it cannot be found.
6. Start the application → landing page **Open Figure Package** → the moved file.
7. Expected: the same plot with the same colours/labels; status bar says "integrity verified"; no dialog asks for a data
   file. Check *File → Recent files* shows the package with 📦.

- [ ] identical figure, no data file needed

## TEST 2 — statistics

1. Load `examples/by_plot_type/box_violin/data.csv`, *Box / violin plot with points*; enable **6. Statistics**, Welch t,
   all pairs, brackets on; render.
2. Note the bracket P values.
3. **Save Figure Package**. Close. Reopen the package (File → Open Figure Package…).
4. Expected: brackets and P values identical; no "opened with notes" warning (that warning appears only if recomputed
   statistics differed from the stored StatsSpec).
5. Unzip a copy of the package (it is a ZIP): `stats_spec.json` must list every comparison with statistic, p_value,
   adjusted_p_value, effect_size.

- [ ] statistics survive the round trip

## TEST 3 — matrix

1. Open a feature × sample matrix (e.g. `examples/matrix_workflow/normalized_feature_matrix.tsv` or your own).
2. **🧮 Matrix workflow…**: confirm the mapping and value scale, assign groups, apply a preprocessing chain (e.g. log2 →
   row z-score), **Open in plot editor** for the heatmap (repeat for PCA if you like).
3. **Save Figure Package**. The dialog must list *two* tables: the source matrix (+ original file) and the derived
   (plotted) table, and the records MatrixSpec, SampleMetadataSpec, PreprocessingSpec.
4. Close; move the package; remove access to the original matrix file; reopen.
5. Expected: heatmap identical; no warning. (If the recorded chain no longer reproduced the frozen derived matrix, a
   warning would say so and the frozen matrix would still be drawn.)

- [ ] matrix preprocessing survives the round trip

## TEST 4 — preset vs package

1. From the TEST 1 plot: **Figure preset → Save preset…** (style) as `Lab scatter`, and **Save Figure Package** as
   `test4.mmfpackage`.
2. Load a *different* table (e.g. `examples/by_plot_type/dose_response/data.csv` or any x/y table), choose the scatter,
   map columns, **Apply** `Lab scatter`.
3. Expected: the new data take the saved appearance (palette order, marker, fonts); values and labels come from the new
   table.
4. **Open Figure Package** → `test4.mmfpackage`.
5. Expected: the ORIGINAL figure with the ORIGINAL data returns.

- [ ] Preset transfers appearance to new data; Package reproduces the original figure

## TEST 5 — original data changed

1. Save a package from any plot made from a CSV you can edit.
2. Edit the CSV in a text editor: change several values, save.
3. **Open Figure Package** → the figure must be unchanged (frozen data).
4. Also: File → **Open PlotSpec…** with a `.plot_spec.json` exported *after* this branch (Export PlotSpec JSON) and the
   edited CSV next to it → a dialog "Data differ from the saved PlotSpec" must appear before the (changed) figure is
   drawn.

- [ ] changing the original data does not change the package result; PlotSpec reopen warns

## TEST 6 — package corruption

1. Copy a package, rename the copy to `.zip`, open `data/<table>.mmftable.json` in a text editor, change one number,
   save, and re-zip with the same file names (or edit inside the archive with 7-Zip). Rename back to `.mmfpackage`.
2. **Open Figure Package** → expected: "Could not open figure package — Package integrity check failed: data differ
   from the values recorded when the package was created (…)". Nothing is rendered.
3. Also try a text file renamed to `.mmfpackage` → "not a valid ZIP container"; and delete `plot_spec.json` from a copy →
   "The package is incomplete".

- [ ] tampered package is detected

## TEST 7 — composite

1. Save two or three plots as panels (**Save current plot as panel**), optionally **Import panel from file…** (a PNG).
2. **Open Figure Builder…**, arrange columns and sizes, **Save Figure Package…**.
3. Close the application. Reopen it, **Open Figure Package** → the composite package.
4. Expected: the Figure Builder opens with the same panels, order, letters, sizes and columns; imported image present;
   preview identical; **Save figure…** and **Save Figure Package…** work from there.

- [ ] composite package works

## TEST 8 — Export all and the three artifacts

1. **Export all as ZIP** for a plot with statistics. Expected ZIP content: `<stem>.svg/.png/.pdf`,
   `<stem>.plot_spec.json`, `<stem>.stats_spec.json`, `<stem>.mmfpackage`, `README.txt`.
2. Help → **Files & reproducibility** tab: PlotSpec / Figure preset / Figure package explained.
3. Tooltips of *Export PlotSpec JSON (specification only)* and *Save Figure Package* read as intended.

- [ ] Export All contains the appropriate provenance; the UI distinction is clear
