# Phase 1 — capability matrix

`plot_capability_matrix.csv` is generated by `build_capability_matrix.py` from the
live registry, UI option declarations, style-capability table and example manifest.
It is never hand-edited: a hand-typed matrix goes stale the first time a plot type
is added, and a stale audit is worse than none.

45 registered plot types.

## Universal capabilities (7)

These must be guaranteed by shared architecture, so a new plot type inherits them:

* `title`
* `figure_size`
* `export`
* `publication_check`
* `PlotSpec`
* `FigurePackage`
* `example_data`

## Plot-specific capabilities (3 or fewer plots)

* `arrows` — volcano_plot
* `cluster_colors` — heatmap_clustered_matrix, hierarchical_clustering
* `column_clusters` — heatmap_clustered_matrix
* `column_labels` — heatmap_clustered_matrix, hierarchical_clustering
* `counts` — volcano_plot, ma_plot
* `dendrogram` — hierarchical_clustering
* `edge_colors` — network_graph
* `faceting` — stacked_bar_composition, spatial_categorical_map, spatial_feature_map
* `label_background` — volcano_plot
* `label_repulsion` — volcano_plot, lollipop_mutation_plot, network_graph
* `node_colors` — network_graph

* `row_labels` — heatmap_clustered_matrix, hierarchical_clustering
* `semantic_colors` — volcano_plot, ma_plot

## Corrections made while building it

The first version of the detector reported `row_clusters`, `column_clusters`,
`label_background` and `faceting` as 0/45 while those controls are plainly visible
in the running application. The patterns were wrong, not the software: the real
keys are `cluster_k_rows`, `cluster_k_columns`, `label_box`, and faceting is a
column *mapping* rather than a style option. Corrected and re-derived.

## Gap found by the audit

The clustered heatmap exposes **no dendrogram control** (`dendrogram = -`), although
Phase 7 requires visibility, line width, colour, padding and relative size. This is
a genuine missing capability rather than a layout defect, and is scheduled for
Phase 7 rather than patched here.
